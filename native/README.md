# Пиратский трактир — Windows и Android 2.0

**Windows передаёт экран и звук; Android смотрит.** Новые нативные комнаты используют собственный протокол **Абордаж/1**. Видеотракт работает без WebRTC PeerConnection/RTP, адаптивного уменьшения битрейта и отдельного кодирования на каждого зрителя. Полное описание: [`protocol/ABORDAGE.md`](../protocol/ABORDAGE.md).

## Запуск

1. Обновите Docker-сервер по основному README. Дополнительно откройте **3480/UDP** (либо свой `ABORDAGE_PORT`) на сервере и в панели хостинга. HTTPS и сертификаты остаются прежними.
2. В Windows распакуйте **весь** архив приложения. Внутри нужен `ffmpeg/bin/ffmpeg.exe` вместе с DLL, assets и библиотекой Абордажа. Запустите приложение.
3. Введите HTTPS-адрес и свой код комнаты. Недоверенный сертификат по-прежнему можно подтвердить для подключения; импорт root.crt необязателен.
4. Найдите экран, выберите монитор с пометкой «Абордаж», звук и GPU-кодировщик. Начальные параметры: **1080p, 120 FPS, 50 Мбит/с, Авто · GPU**. Нажмите «Поднять флаг и отчалить».
5. Друг вставляет полную ссылку и код в новом Android/Windows клиенте.

Монитор и игра должны выдавать как минимум 120 различных кадров/с. Частота до 480 FPS доступна как запрос; кодировщик может повторять неизменившийся кадр для подключения новых зрителей. Счётчик encoded FPS включает такие повторы; новые фазы движения требуют соответствующей частоты источника/монитора. Захват отдельного окна через gdigrab оставлен до 60 FPS. Браузер смотрит только старые браузерные WebRTC-комнаты; комнату Абордажа нужно открывать нативным клиентом. Новый клиент умеет смотреть и старые браузерные комнаты.

## Захват, кодирование и звук

- Экран захватывает отдельный FFmpeg-процесс через DXGI (`ddagrab`), что также отделяет его от DXGI-миниатюр выбора экрана в клиенте. GPU D3D11 выполняет масштабирование/NV12. Для NVENC/AMF кадры остаются на GPU; QSV использует копирование NV12, явный CPU-режим — программную конвертацию после чтения BGRA.
- Кодек H.264: NVIDIA NVENC, AMD AMF, Intel QSV. «Авто · GPU» пробует их по очереди и показывает ошибку, если ни один не запустился. Программный libx264 доступен **явным** выбором «CPU · H.264». Автоматического скрытого перехода на CPU нет.
- B-кадры и lookahead отключены; короткий GOP около 250 ms. NVENC использует ultra-low-latency, delay=0. Параметры — цель, а не обещание производительности.
- Выбор звука: весь системный звук / без звука / одно приложение с дочерними процессами. WASAPI process loopback требует Windows build 20348+ (Windows 11 / Server 2022). Для Абордажа — stereo 48 кГц, AAC 192 кбит/с, короткий буфер. Недоступный выбранный источник не заменяется всеми системными звуками.
- Android декодирует H.264 через MediaCodec, Windows — через D3D11VA; видеовывод — нативный libmpv/media_kit. Android запрашивает максимальную частоту экрана при текущем разрешении. Решение остаётся за ОС/энергосбережением.
- UDP с шифрованием/FEC работает в отдельном isolate. Капитан передаёт одну копию на сервер, сервер рассылает зрителям. Требуемый исходящий канал сервера растёт с числом зрителей.

Предпросмотр капитана выключен по умолчанию; при включении его локальный звук заглушён, чтобы не создавать эхо. Статистика свёрнута и показывает фактическую частоту кодирования, битрейт, FEC/потери и данные декодера. `estimated-vf-fps` плеера — оценка по видеопотоку, а не измерение обновлений физического дисплея. Реальные ошибки доступны в состоянии подключения.

## Чат и сертификаты

Текстовый чат и пиратские прозвища общие с браузером. Микрофон включается только кнопкой вступления в голос. Голосовое общение пока использует отдельный WebRTC audio-only mesh и TURN из настроек сервера; видеопоток Абордажа от него не зависит. Рекомендуются наушники.

TLS-доверие привязано к точному HTTPS origin и SHA-256 сертификата. Смена сертификата вызывает новый вопрос; «Только сейчас» не сохраняет исключение. «Сбросить доверие» очищает CA/отпечаток выбранного сервера. Подтверждение сертификата не отключает проверку TLS для других адресов. Приватные ключи импортировать или передавать не нужно.

При закрытии капитана или сервера комната заканчивается. Автоматического переподключения/нового захвата без участия пользователя нет. UDP должен быть доступен; TCP fallback не используется.

## Сборка

Зафиксированы Flutter **3.38.5 / Dart 3.10.4**, flutter_webrtc **1.6.3** (legacy browser video, picker и optional voice), media_kit, Monocypher **4.0.2**. Нативная FFI-библиотека шифрования входит в Android APK/Windows portable.

```sh
cd native
python tool/bootstrap.py
flutter pub get --enforce-lockfile
flutter analyze
flutter test
```

Windows: Visual Studio 2022 Desktop development with C++ и Windows SDK:

```powershell
flutter build windows --release
python tool/bundle_ffmpeg.py
```

Скрипт получает закреплённый SHA-256 отдельного FFmpeg executable из `tool/ffmpeg-windows.json` и копирует его вместе с лицензиями, документацией и происхождением сборки. FFmpeg — отдельный GPL executable; Monocypher — отдельный набор исходников с собственной лицензией. Не удаляйте сопровождающие лицензии из распространяемого комплекта. Распространяйте всю папку `build/windows/x64/runner/Release`. На чистом Windows может потребоваться Microsoft Visual C++ Redistributable x64. Приложение не подписано коммерческим сертификатом.

Android: JDK 17, Android SDK 36/NDK/CMake:

```sh
flutter build apk --release --target-platform android-arm64,android-arm
```

APK — `build/app/outputs/flutter-apk/app-release.apk`. CI использует тестовый debug signing key; для постоянных обновлений настройте свой signing key в секретах, не в Git. Разные CI-ключи могут потребовать переустановки с потерей локальных настроек.

## Проверки

Серверные тесты проверяют комнаты, TLS control Origin, изоляцию, подписи/повторы UDP, запрет публикации зрителю, закрытие регистраций и чат. Нативные тесты сверяют независимые реализации XChaCha20-Poly1305, подмену заголовков, FEC, истечение потерянных блоков, конфигурацию GPU/высокого FPS, интерфейс и доверие сертификатам.

Для Linux benchmark нужны Node 24, Python, C compiler и FFmpeg с libx264. После `flutter pub get`:

```sh
sh tool/test_abordage.sh
```

Он компилирует release Dart benchmark и нативную криптобиблиотеку, кодирует **320×180/480 FPS/25 Мбит/с** и **640×360/240 FPS/50 Мбит/с**, передаёт через настоящий Node UDP relay с искусственными потерями/перестановкой, восстанавливает и декодирует. Timestamp в пикселях измеряет путь от генерации кадра до декодирования. Логи — `build/abordage-benchmark/`. Это не проверка DXGI/NVENC/MediaCodec и 1080p/120 на конкретном ПК/телефоне.

GitHub Actions собирает Windows x64 и Android APK, выполняет анализ/тесты, проверяет наличие нужных FFmpeg filters/encoders и публикует артефакты `Pirate-Tavern-Windows-x64`, `Pirate-Tavern-Android-APK`, `Abordage-Regression`. Скачивайте из завершившегося успешного запуска. Подтверждение **1080p/120** требует измерения кодирования и декодирования на реальных устройствах с подходящими GPU/экраном и достаточной сетью.
