# Измерения Абордажа, 13 ноября 2026

Облачный Linux x86_64, 5 видимых vCPU Intel Xeon Platinum 8573C, FFmpeg 7.1.5, Dart 3.10.4 AOT. Физических GPU/Windows/Android в этой среде нет. Синтетическое изображение содержит движущийся testsrc2, шум и бинарный timestamp. Полный путь: H.264 libx264 → шифрование → UDP proxy с потерями/перестановкой → настоящий Node relay → FEC/повторы → расшифровка → H.264 decode. Порог регрессии проверяется автоматически; сырые логи доступны в артефакте CI.

| Запрос | Декодировано | Принято | Latency p50 / p95 | Ошибки декодирования | Результат |
|---|---:|---:|---:|---:|---|
| 320×180, 480 FPS, 25 Мбит/с | 479,1 FPS | 27,4 Мбит/с | 17 / 49 ms | 0 | PASS |
| 640×360, 240 FPS, 50 Мбит/с | 234,5 FPS | 51,7 Мбит/с | 32 / 71 ms | 0 | PASS |
| 1920×1080, 120 FPS, 50 Мбит/с, CPU | 20,5 FPS | 9,3 Мбит/с | 729 / 1413 ms | есть | FAIL |

В двух успешных прогонах нет потерянных блоков/пропусков очереди. Восстановлено 861/1407 блоков FEC и выполнено 10/25 повторных отправок. Некорректных timestamp в этих прогонах не было. Зритель подключался после начала эфира; перед измерением выполнялся прогрев. Битрейт включает MPEG-TS, без внешнего MAC/FEC, поэтому выше бюджета elementary video.

HD-прогон **не прошёл**: программное кодирование/шумовая генерация в этой CPU-среде не успевали, возникали пропуски и ошибки. Эти данные не подтверждают 1080p/120. Основной Windows-путь использует другой, аппаратный захват/кодирование (D3D11 + NVENC/AMF/QSV), но его производительность и MediaCodec на телефоне необходимо измерить на физических устройствах. Наличие GPU-кода или успешной компиляции не заменяет такой проверки.

Latency измеряется по wall-clock в декодированных пикселях на одной машине. Она включает генерацию timestamp, encode, транспорт и decode, но исключает физическую развёртку дисплея и домашний WAN. Результаты не следует переносить на интернет-соединение без дополнительного замера.
